# 自动化任务模块 UI 评审与优化方案

> 状态：**评审完成，未实施**。本文档只提出问题与方案，不包含代码改动。
> 相关文档：[ui-review-round2.md](ui-review-round2.md)（全站第二轮评审及刷新控件规范 R1–R5）、[automation-module-plan.md](automation-module-plan.md)（模块设计）、[docs/rules/frontend.md](../rules/frontend.md)（前端工程约定）。

- 评审对象：`frontend/src/views/automation/*`（4 页共 1675 行）+ `App.vue` 壳层 + `components/LogViewer.vue`
- 评审日期：2026-11-06
- 基线版本：**4.13.2**（commit `f58f2ed`）
- 评审方法：启动真实前后端（后端 `:8000` 已有 1 条自动化任务数据），用 Playwright 在 1440×900 / 1280×860、明色与暗色下逐页截图，并**逐项量取 DOM 矩形、滚动宽度、行高与标签对比度**；每条结论都标注了实测值与源码行号，未凭截图猜测
- 度量脚本：`.workbuddy/tmp/audit-automation.mjs`、`measure-auto.mjs`、`measure2.mjs`（实施后可直接重放验证）

## 1. 总体结论

这套界面**能跑通、也不难看**，三个页面骨架统一（工具栏 + 卡片表格 + 分页），令牌与暗色都继承了既有体系，没有硬编码颜色（`views/automation` 下十六进制色值 0 处）。问题集中在三处：

1. **表格装不下**：任务历史 10 列合计 1586px，容器只有 1138px，右侧 448px 落在可视区外，又被固定操作列压住——**缺失文件、链路、起止时间默认看不见**。这不是审美问题，是信息丢失。
2. **模块的核心价值在界面上不可见**：自动化的卖点是「上传 → 校验可见 → STRM」这条链 + 轮次循环，但四个页面都是通用 CRUD 表格，链路只剩一个灰色文字标签，实时日志只有文本流。用户看不出「自动化」到底自动了什么。
3. **内部实现细节漏到了界面**：`waiting_openlist_check` 这类英文枚举、`上传任务（B）` 这类引擎代号 A/B、精确到微秒的时间戳，都在要求用户理解程序内部结构。

**判断**：不需要重做布局，需要一次**表格层级重排 + 一个链路状态组件 + 一轮文案收敛**。

## 3. 优化方案

### 3.1 表格信息架构重排（对应 P0-1、P0-2、P0-3、P2-2）

**原则**：一列只承载一类语义；宽度预算按 **1280 视口容器 978px** 反推（比 1440 更严），不再允许默认视口出现横向滚动。

#### 任务历史：10 列 → 5 列（1586px → 960px）

| 列 | 内容 | 宽度 | 说明 |
|----|------|------|------|
| 任务 / 轮次 / 时间 | 任务名（主行）／第 N 轮 · 编号 #id（副行）／`11-06 09:15:20 → 09:15:31`（小字） | min-width 260 | 合并原「任务/轮次」「开始时间」「结束时间」三列；时间用 `formatDateTime` 后再裁成 `MM-DD HH:mm:ss` |
| 结果 | 状态标签 + 阶段（`成功 · 本轮完成`） | 170 | 合并原「状态」「阶段」两列 |
| 文件流水 | `新增 1 · 校验 0 · 跳过 0 · 缺失 3`，缺失 > 0 时用 danger 色加粗 | 210 | 合并原四个数字列；数字列保持 `tabular-nums` 右对齐 |
| 链路 | `上传 #12 成功 → STRM #9 成功`，失败段红色 | 180 | 替代「A / B 执行」两行文本，语义化 |
| 操作 | 详情 / 日志 / `⋯`（重试失败收进菜单） | 140 | 三个动作收成两个 + 菜单 |
| 合计 | | **960** | 1440 余 178px，1280 余 18px |

#### 执行管理：7 列 → 6 列

| 列 | 内容 | 宽度 |
|----|------|------|
| 任务 / 链路 | 任务名（主行）／`上传任务 → STRM 任务`（副行）／`第 3 轮 · 上次扫描 09:15`（小字） | min-width 220 |
| 校验目录 | 单行省略 + tooltip | 150 |
| 运行状态 | **链路状态条**（见 3.2）+ 状态标签 | 200 |
| 待校验 | 数字，>0 用 warning 标签 | 80 |
| 下一轮 | 倒计时 `00:42`（见 3.5） | 90 |
| 操作 | 启动/停止（主按钮 `link primary`）+ `⋯`（重置指纹 / 清空待校验 / 日志） | 140 |
| 合计 | | **924** |

「最近扫描」列删除，时间并入首列小字；操作列 290 → 140 后不再换行（实测 4 个按钮需 ~266px，主按钮 + 菜单只需 ~120px）。

#### 任务配置：8 列微调

`任务名称 180（校验目录并入副行）· 上传任务 140 · STRM 任务 140 · 运行参数 130 · 状态 90 · 最近扫描 130 · 操作 110` = **968**，1280 下不溢出（当前 1118，实测溢出 140px）。

### 3.2 新增「链路状态条」组件（对应「模块价值不可见」）

**位置**：执行管理行内（紧凑 24px 高）+ 实时日志顶部（完整 44px 高，附计数）。
**结构**：四段 `扫描 → 上传 → 校验 → STRM`，段状态三态：已完成（绿底）／当前段（主色描边 + 圆点，可加 1.2s 脉冲）／未开始（中性灰）。
**数据来源**：`phase` 单值映射到段序号，不新增接口。

| phase | 中文标签 | 链路段 | 备注 |
|-------|----------|--------|------|
| `starting` | 准备中 | 0 扫描 | 当前段 |
| `waiting_idle` | 等待 A/B 空闲 | 0 扫描 | 附「等待既有执行结束」tooltip |
| `waiting_upload` | 上传中 | 1 上传 | |
| `waiting_openlist_check` | 校验可见性 | 2 校验 | |
| `waiting_openlist_task` | STRM 生成中 | 3 STRM | |
| `interval` | 等待下一轮 | 全部完成 | 显示倒计时 |
| `backoff` | 失败退避中 | 全部完成（红） | 显示退避剩余 + 连续失败数 |
| `idle` | 空闲等待 | 全部完成 | |
| `stopped` / `done` | 已停止 / 已结束 | 全部完成 | |

**实现要点**：

- 词表抽到 `src/constants/automation.ts` 单一来源，四个页面共用（当前 `Execution.vue:41`、`TaskHistory.vue:43` 两份词表且文案不同：一个「上传中」一个「等待上传完成」）。
- 无障碍：容器 `role="status"` + `aria-label="链路：上传已完成，正在校验 OpenList 可见性"`；不只靠颜色区分（当前段另有圆点与描边）。
- 暗色：已完成段用 `--el-color-success-light-9` 系，当前段用主色 `light-9` + 主色描边，不新增硬编码色。

### 3.3 术语与文案统一（对应 P1-3、P0-4）

- 界面统一说「上传任务」「STRM 任务」「链路」，删除所有 `(A)` `(B)` 后缀；`A` `B` 只保留在日志行 `[A#12]` `[B#9]`（引擎镜像行，是排障需要），并在日志工具条加一个 `A/B 是什么` 的问号 tooltip。
- 阶段词表只保留一份（见 3.2 表），实时日志、执行管理、历史三处引用同一映射。
- 任务历史的 `.page-hint` 删除——顶栏 `description` 已承担说明职责；确需补充操作规则时改用工具栏右侧问号 tooltip（不占首屏高度）。

### 3.4 工具栏与操作层级（对应 P1-1、P1-2）

按 round2 §6 R1 回收：

| 页面 | 左侧组 | 右侧组（从左到右） |
|------|--------|-------------------|
| 任务配置 | 搜索 | 刷新 → 批量删除 → **新建任务** |
| 执行管理 | 运行中统计（`运行中 2 · 待校验 6`） | 刷新 → **批量启动** |
| 任务历史 | 任务筛选 → 状态筛选 | 刷新 → 日志文件夹 |
| 实时日志 | 任务选择 → 连接状态 → 阶段标签 | 重新连接（唯一） |

- 执行管理的页面级「实时日志」入口删除：表格每行已有「日志」，顶栏胶囊也可跳转，同页三个入口属于冗余。
- 实时日志的「加载最近一轮」移到日志区工具条（回放属于内容区动作，不是页面动作），并作为空态里的主 CTA 出现——现在空态只有一句「可加载最近一轮日志回放」，却没有按钮。

### 3.5 时间与倒计时（对应 P0-3、P2-2）

- 表格内一律走 `utils/date.ts`：新增 `formatShortDateTime`（`MM-DD HH:mm:ss`），禁止直接渲染后端原始字符串（微秒问题一次性消失）。
- 「下一轮」显示相对时间：`00:42`（<1h）/ `1h 05m`（≥1h）；数据仍是 5s 轮询的 `next_round_at`，前端用本地时钟做差，不新增接口。
- 悬浮 tooltip 显示绝对时间，兼顾两种需求。

### 3.6 状态标签、空态与危险动作（对应 P2-1、P1-4、P2-3）

- 标签统一为 `size="small" effect="light"`：运行中 `success` + 左侧 6px 脉冲点；失败 `danger`；空闲 `info`；退避 `warning`。暗色下把 `info` 换成中性 `--el-text-color-regular` + `--el-fill-color` 底，避免暖灰被读成警告。
- 四个页面共用一个空态组件（描述 + 一句引导 + 一个 CTA）：执行管理「暂无自动化任务」→ 按钮「去创建任务」直接跳 `/automation/tasks`；实时日志空态 → 按钮「加载最近一轮」。
- **重置指纹加二次确认**，文案说明后果（「下一轮将忽略指纹、重新扫描全部文件」）；三个行内动作按风险分级：启动/停止用 `link primary`，重置指纹 `link`，清空待校验 `link danger`。

### 3.7 表单规格（对应 P2-4）

- 任务配置抽屉分三段：**必填**（名称 / 上传任务 / STRM 任务 / 校验目录）→ **运行参数**（并发 / 重试 / 生成模式）→ **高级（默认折叠）**（4 个超时 + 轮次间隔，每项带默认值与一句话解释）。首访者看到的字段从 12 个降到 7 个。
- 抽屉与弹窗规格统一：编辑用 `el-drawer` + `label-position="top"`（长表单）；轻量操作用 `el-dialog` + `label-width="96px"`。启动弹窗保留 dialog，但标签宽度 120 → 96，与全局一致。

**验收标准**（每批交付前实测，脚本可直接重放）：

1. 1440 / 1280 两档视口下，四个页面 `document.scrollWidth === clientWidth`，且表格容器 `scrollWidth - clientWidth ≤ 0`（历史、执行、任务配置三表均为 0）。
2. 任意行高 ≤ 56px（单行语义），操作列按钮不换行（`button.y` 全部相同）。
3. 时间字段不含小数点后六位；「下一轮」为相对时间。
4. 全模块不再出现 `waiting_*` / `done` / `idle` 等英文枚举（在页面上全文搜索）。
5. 「自动滚动」控件每页恰好 1 个。
6. 刷新按钮位置与 round2 §6 表格一致；主操作恒为右侧组最后一个。
7. 暗色下所有标签对比度 ≥ 4.5:1（当前「空闲」5.24:1，改造后不得下降）。
