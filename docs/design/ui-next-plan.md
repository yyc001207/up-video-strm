## 0. 摘要

### 0.1 本版改了什么（相对首版）

| 维度 | 首版（工程控制台） | 本版（暖调媒体） | 为什么 |
|------|-------------------|-----------------|--------|
| 主色 | 工程蓝 `#2b6cf6` | **暖紫 `#6B4EE6`** + 蜜桃点缀 `#FF8A5B` | 蓝色是"管理系统"的默认色；紫属于内容与娱乐 |
| 表面 | 冷灰 `#f7f8fa` | **奶油 `#FAF7F5`** | 暖底让界面"有体温"，不像监控台 |
| 圆角 | 6 / 8 / 12 | **10 / 16 / 20 / 999** | 更亲和的触感 |
| 导航 | 64px 图标栏 + 200px 页面列表 | **单列 232px 手风琴** | 图标栏是 IDE / 运维台语言 |
| 列表 | 40px 表格为主 | **56px 卡片列表为主**，表格仅用于运行记录 | 表格是"数据"，卡片是"内容" |
| 标题 | 20px，在顶栏 | **28px，在内容区** | 大标题 + 留白是 C 端阅读节奏 |
| 状态 | 圆点 + 文字 + 琥珀徽标 | **柔和胶囊 + 进度环 + 顶栏运行入口** | 状态要"看得懂"，不是"读得懂" |
| 文案 | 执行管理 / 任务配置 / 实时日志 | **开始执行 / 任务 / 运行详情** | 系统术语 → 用户语言 |

### 0.2 判断：B 端感从哪来

1. **冷色 + 冷灰**：`#2b6cf6` 主色、`#f7f8fa` 页面底、`#d9dee6` 描边——管理后台的标准三件套。
2. **密度**：表格行 40px、表头 12px、工具条 32px，一屏塞 18 行，是"看数据"的节奏。
3. **导航结构**：模块按钮 + 页面组堆叠在 220px 一列里；首版还加了图标栏——都是 IDE / 运维台语言。
4. **术语**："执行管理""任务配置""触发方式""批量删除"，是系统在描述自己，不是人在描述目的。
5. **状态语气**：圆点 + 文字、琥珀色警告徽标、"提示"标题的确认框，机器口吻。
6. **空态**：默认 `No Data` / "暂无数据"，没有下一步。

### 0.3 五个动作

| # | 动作 | 解决什么 |
|---|------|----------|
| A | 换"温度"：暖紫 + 奶油 + 大圆角 + 大标题 | 第一眼不再像后台 |
| B | 导航降一层：单列侧栏，模块即分区 | 去掉 IDE 感，模块切换仍记忆位置 |
| C | 列表卡片化：任务有"头像"，状态有"语气" | 从"行"变成"条目"，降低阅读压力 |
| D | 首页变成「今天」：一句概览 + 三张流水线卡 | 打开先看到结果，不是配置 |
| E | 全站文案重写 + 顶栏运行入口 | 说人话；运行状态随手可看，且不遮挡任何内容 |

## 1. 目标、用户与边界

### 1.1 用户

单人自建媒体库用户，Windows 桌面常驻，把工具当"家里的影音管家"。他们不是运维，不想理解"增量 / 全量 / 触发方式"，只想知道：**新剧集有没有进库、昨晚跑成功没有、失败的那几集怎么办**。

### 1.2 C 端用户对界面的期待 → 设计应答

| # | 期待 | 现状 | 设计应答 |
|---|------|------|----------|
| H1 | 打开就知道"今天怎么样" | 落在全局配置页 | 「今天」首屏：一句概览 + 三条流水线 + 待处理 |
| H2 | 不想读表格，想"扫一眼" | 40px 表格、12px 表头、8 列信息 | 卡片列表：头像块 + 两行文字 + 一个状态胶囊 |
| H3 | 出错时只想知道"哪几集、怎么办" | 日志原文、错误码 | 失败清单 + 「重跑这几集」；日志作为证据放在第二层 |
| H4 | 不想被术语教育 | 执行管理 / 任务配置 / 触发方式 | 开始执行 / 任务 / 运行记录（路由不变） |
| H5 | 怕点错，但更怕被弹窗打断 | 每个删除都弹确认 | 可撤销的操作给 5 秒撤销；只有不可恢复才弹 |
| H6 | 喜欢"有反应"的界面 | 只有 toast | 悬停轻抬升、状态胶囊淡入、进度环补间（均尊重减弱动效） |
| H7 | 夜间使用 | 深色是灰阶反色 | 深色用紫黑，不是纯灰；语义色重新取值 |
| H8 | 依然是桌面工具用户 | — | 保留批量、键盘、路径复制、打开文件夹，不因"好看"砍效率 |

### 1.3 非目标

移动端、多用户 / 权限、报表大屏、登录体系、国际化；也不做"装饰性插画系统"（无美术资源，靠比例、色彩与排版建立气质）。

### 1.4 成功标准

| # | 标准 | 判定 |
|---|------|------|
| M1 | 非技术用户第一次打开，30 秒内说出"现在有没有在跑、有没有失败" | 5 人可用性走查，4/5 通过 |
| M2 | 任务列表页不出现表格线，仍能完成批量删除 | 交互走查 |
| M3 | 首屏（1440×900）至少 3 个任务卡片完整可见 | 截图核对 |
| M4 | 12–14px 文字对比度全部 ≥4.5:1 | 第 6.3 节逐项 |
| M5 | 从任意页面 1 次点击看到运行中任务的进度 | 顶栏运行胶囊 → 抽屉 |
| M6 | 三个执行页共用一套模板与样式 | 代码评审 |
| M7 | 落地不新增后端接口，`frontend/src/api` 无新增方法 | 代码评审（diff 仅前端视图 / 组件 / 样式） |

### 1.5 接口与数据约束（硬约束）

本方案的所有新视觉元素，都必须能在**现有接口返回的字段**上算出来。做不到的，就降级或不做，而不是加接口。

| # | 约束 | 具体做法 |
|---|------|----------|
| C1 | 不新增后端接口与字段 | 不做 `/overview`、`/dashboard` 之类的聚合端点；不修改现有 `Res` 结构与分页参数 |
| C2 | 新页面只做客户端聚合 | 「今天」并行调用已有查询接口，前端合并排序；不做"为某个卡片定制"的服务端统计 |
| C3 | 派生数据一律前端算 | 概览句、百分比、剩余时间估算、头像颜色、待处理数、Token 到期天数，全部由已有字段推导 |
| C4 | 缺字段优先降级 | 字段不存在就隐藏该项或显示"还没跑过"，不为了补齐 UI 向后端要字段 |
| C5 | 请求预算 | 单页首屏 ≤ 5 个请求；轮询复用 `stores/running.ts` 的 30s 节奏；不为新组件单独加轮询 |
| C6 | 分页边界 | 客户端合并只取第一页（20 条）；文案避免"共 N 个""全部"这类全量断言，改用"最近""当前" |
| C7 | 例外流程 | 若确需新字段，单独走接口评审与版本递增，不夹带在 UI 改造里 |

**明确不做的效果**（因为现有数据支撑不了，且不值得为它加接口）：

- 任务封面 / 海报：没有图片接口，头像块用名称首字 + 哈希色代替。
- 运行时长趋势、成功率曲线：没有按时间聚合的统计接口。
- 全站"今日总览"精确统计：只统计第一页可见的执行记录，文案写"最近"。
- 服务器在线状态的实时探测：`OpenListServer` 没有状态字段，只有 `test-connection`；「今天」不主动探测，只在「连接与格式」页按现有 60s 节奏检测。
- 自动化"下次运行时间"的保证值：`next_round_at` 只在运行中存在，未运行时显示轮询间隔而不是编造时间。

## 2. 现状诊断（代码事实）

### 2.1 结构

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| S1 | 默认页是配置页 | `router/index.ts`：`/` → `/config`，catch-all 同 | 每天第一次打开落在一次性配置页 |
| S2 | 导航一列塞三级信息 | `App.vue` 220px 内先 4 个模块按钮（36px/项），再当前模块页面组；`goModule()` 跳该模块首页 | 切模块丢上下文；再加模块必然滚动 |
| S3 | 同名页面三份实现 | 执行页 990 / 911 / 1291 行；日志页 830 / 553 / 587 行 | 同一问题要修三次；样式漂移 |
| S4 | 主行动位置不统一 | 执行按钮在卡片底部、新建在工具栏右侧、保存在抽屉底部 | 每页都要重新找"下一步" |

### 2.2 交互

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| I1 | 运行状态只在二级页 | 徽标挂在「实时日志」导航项；顶栏不提供状态入口 | 想知道在跑什么，必须离开当前页 |
| I2 | 日志是"目的地" | 启动后 `router.push('/xxx/realtime?execs=...')` | 离开即失去监控 |
| I3 | 首访双空态 | 任务配置页同时有参数卡空态与表格空态 | 不知道先做什么 |
| I4 | 反馈要么吵要么静 | 轮询失败曾每 5–10s 弹 toast（已修）；但无"数据多久没更新"的证据 | 分不清"空闲"与"挂了" |

### 2.3 视觉（实测）

| # | 问题 | 实测 | 结论 |
|---|------|------|------|
| V1 | 导航徽标：琥珀底 + 白字 | **2.35:1** | 不合格，且琥珀被读成"警告" |
| V2 | 导航选中：主色文字 + 12% 主色底 | **3.90:1** | 14px 文字不合格 |
| V3 | `#12b76a` 作文字 | **2.62:1** | 语义色当文字用，不可读 |
| V4 | 焦点环不完整 | `global.scss` 只有 `outline-offset` | 深色 / 浅色表现不一致 |
| V5 | 字体栈以 macOS 字体开头 | `Helvetica Neue` / `PingFang SC` 在 Windows 不存在 | 中文落雅黑、拉丁也落雅黑；600 即 Bold 会跳宽 |

### 2.4 结论

界面不是"不好看"，是**在用管理系统的语法讲一个家庭影音的故事**。因此本版不动技术与功能，只改四件事：**颜色与比例、信息的密度与容器、状态的表达方式、说人话的文案**。

## 3. 设计原则

| # | 原则 | 做法 | 反例 |
|---|------|------|------|
| P1 | **先给结果** | 页面第一屏先回答"成了没、在跑没"，参数与明细后退 | 进执行页先看到一屏参数 |
| P2 | **内容是主角** | 任务 / 剧集有头像、有名字、有一句摘要；容器退到背景 | 一屏表格线，任务只是行 |
| P3 | **温度来自比例与语气** | 暖色、大圆角、留白、动词化文案；不靠插画和渐变 | 加渐变背景假装"设计感" |
| P4 | **高级能力后退一步** | 参数收进「更多设置」，批量与键盘始终可用 | 为了简洁砍掉批量 |
| P5 | **桌面原生** | Windows 字体、DPI、路径复制、资源管理器、快捷键 | 照搬移动端手势 |

## 4. 信息架构

### 4.1 导航：单列侧栏 + 模块手风琴

```
┌──────────────────────┬──────────────────────────────────────────────┐
│ ◉ up-video-strm      │  搜索…      ● 2 个在跑 38%   ● 已连接   ◐   │ 48
│                      ├──────────────────────────────────────────────┤
│ 今天                 │  今天                                        │
│ ▾ STRM 生成          │  3 个任务跑完了，1 个需要看一眼              │
│    任务               │                                              │
│    开始执行    ● 2   │  ┌ 流水线卡 ─┐┌ 流水线卡 ─┐┌ 流水线卡 ─┐   │
│    运行详情          │  │           ││           ││           │   │
│    运行记录          │  └───────────┘└───────────┘└───────────┘   │
│ ▸ 云盘上传           │                                              │
│ ▸ 自动追更           │  需要处理                                    │
│ ──────────────       │  · 3 个文件没传上去              [去处理]     │
│ 连接与格式           │                                              │
│ 设置          ◐      │  最近活动                                    │
└──────────────────────┴──────────────────────────────────────────────┘
```

| 元素 | 规格 |
|------|------|
| 侧栏 | 宽 232px；可折叠为 72px 图标栏（记住状态）；背景 `surface`，右侧 1px 弱描边，无阴影 |
| 品牌 | 32px 圆角方块 + 名称 15/600；折叠时只留方块 |
| 模块标题 | 高 44px，图标 20 + 名称 15/600；仅在悬停 / 当前模块显示展开箭头 |
| 子项 | 高 40px，左缩进 44px；选中 = 主色 12% 底 + 主色文字；**不加左侧竖条**（太工具化） |
| 展开规则 | 只展开当前模块；点其他模块 = 展开并回到该模块上次页面 |
| 徽标 | 只在「开始执行」显示运行中数量；主色底白字，18px 高胶囊 |
| 底部 | 「连接与格式」「设置」+ 主题切换；与上方用 1px 分隔线隔开，留 12px 呼吸 |

**为什么放弃首版的"图标栏 + 页面列表"**：两层导航要求用户先记住图标语义，是 IDE / 运维台的心智；C 端应用只有一层。4 个模块 × 4–5 页，单列完全放得下（约 520px），且切换模块不需要跳页。

### 4.2 页面与命名

路由**全部不变**，只改展示名。命名是本版最直接的"去 B 端化"手段：

| 现展示名 | 展示名（已确认） | 路由 | 说明 |
|----------|-----------|------|------|
| 任务调度（模块） | **STRM 生成** | `/schedule/*` | 说结果，不说机制 |
| 任务配置 | **任务** | `/schedule/tasks` | 去掉"配置"的行政感 |
| 执行管理 | **开始执行** | `/schedule/execution` | 动词，指向动作 |
| 实时日志 | **运行详情** | `/schedule/realtime` | 日志是证据，不是目的 |
| 任务历史 | **运行记录** | `/schedule/history` | 更直白 |
| 上传管理（模块） | **云盘上传** | `/upload/*` | 说对象 |
| 重命名规则 | **命名规则** | `/upload/rename` | 少一个动词 |
| 自动化任务（模块） | **自动追更** | `/automation/*` | 用户真正想要的结果 |
| 全局配置 | **连接与格式** | `/config` | 说明里面是什么 |
| 总览（新增） | **今天** | `/` | 默认页 |

> 展示名已确认**全量改写**（含模块名）；路由保持不变，文档、用户手册、截图与代码中的标题按上表同步。改名后不再出现"配置 / 执行管理 / 实时日志 / 触发方式"等系统词。

### 4.3 路由与不变项

| 项 | 处理 |
|----|------|
| `/` | 由重定向 `/config` 改为渲染「今天」 |
| catch-all | 重定向 `/` |
| `/schedule/config` | 仍重定向 `/config` |
| `/settings` | **不可变**：托盘经 `window.__upVideoStrmNavigate('/settings')` 跳转 |
| 其余 13 条业务路由 | 路径不变，仅页面实现替换；`?execs=` 保留为上下文接力 |

### 4.4 全局入口

| 入口 | 触发 | 内容 | 阶段 |
|------|------|------|------|
| 顶栏运行胶囊 | 常驻顶栏（吸顶） | 显示「N 个在跑 · 百分比」，点击开右侧 420px 抽屉：运行中任务、停止、看详情 | P2 |
| 搜索 | 顶栏胶囊 / `Ctrl+K` | 页面、任务、动作 | P2 |
| 快捷键 | `Alt+1..4` 模块、`/` 搜索、`Esc` 关闭、`Ctrl+Enter` 执行 | — | P1 |

## 5. 布局系统

### 5.1 壳层

| 令牌 | 值 | 说明 |
|------|----|------|
| 侧栏宽 | 232px（折叠 72px） | 单列手风琴 |
| 顶栏高 | 48px | 只放全局工具，不放页面标题 |
| 内容内边距 | 32px（<1280 为 24px） | 大留白是 C 端节奏 |
| 内容最大宽 | 1360px | 超宽屏留白居中 |

### 5.4 滚动与固定

- 一个视口只有一个纵向滚动容器；页面本身不出现整页滚动条（沿用现有约定）。
- 顶栏吸顶（48px，白底 + 1px 下边线）：它是运行状态唯一的常驻入口，滚走就失去价值；内容区从顶栏下方开始滚动，侧栏独立滚动。
- 工作台侧栏 sticky，底部按钮区 72px 常驻。
- 抽屉锁背景滚动；关闭后焦点回到触发元素。

### 7.8 反馈

| 类型 | 场景 | 规格 |
|------|------|------|
| 行内 | 校验、目录不可用 | 控件下方 13px，不打断 |

### 7.10 顶栏运行入口（ActivityChip + ActivityDrawer）

- **不使用悬浮球**：桌面窗口里任何浮动元素都会盖住表格与按钮，贴边拖动又与窗口吸附冲突；运行状态改为顶栏常驻胶囊。
- 胶囊：高 28，圆角 999，`padding 0 10`；有运行时 `● 2 个在跑 · 38%`（紫点 + 常规色文字，数字等宽）；有待处理时追加 `· 1 待处理`（琥珀点）；无运行时显示 `空闲`（中性，不呼吸、不高亮）。
- 百分比**不额外发请求**：`stores/running.ts` 现在的 `listExecutions` 已是 `pageSize:1`，改为 `pageSize:5` 并缓存运行中执行的计数字段，前端按"成功数 / 总数"加权；当运行数 >5 时只显示数量、不显示百分比（样本不全，不猜）。
- 点击：右侧抽屉 420（圆角 20，遮罩 32%），两组内容——运行中（头像 + 名称 + 进度 + 停止 + 看详情）、最近完成（2 条）。抽屉可 `Esc` 关闭，焦点归还胶囊。
- 抽屉内「看详情」跳运行详情页；**不提供**日志过滤 / 下载 / 重连，避免变成第二个日志页。
- 顶栏因此吸顶（见 5.4）。1024–1279 宽下胶囊缩为 `● 2`，只留数字，`aria-label` 保留完整描述。

### 9.1 状态词表

| 域 | 词 | 颜色 |
|----|----|------|
| 执行 | 排队中 / 运行中 / 成功 / 失败 / 已取消 | 中性 / 紫 / 绿 / 红 / 中性 |
| 从未执行 | 还没跑过 | 中性 |
| 文件 | 待上传 / 上传中 / 已上传 / 跳过 / 失败 | 中性 / 紫 / 绿 / 中性 / 红 |

| 连接 | 已连接 / 离线 / 未连接 / 检查中 | 绿 / 红 / 中性 / 中性 |

同一个词只有一个含义："完成"不再既指"执行结束"又指"成功"。

### 9.2 文案改写对照

| 现在 | 改成 | 为什么 |
|------|------|--------|
| 暂无数据 | 还没有任务。先添加一个剧集目录吧 | 给下一步 |
| 执行管理 | 开始执行 | 动词化 |
| 任务配置 | 任务 | 去掉行政感 |
| 实时日志 | 运行详情 | 日志是证据 |
| 触发方式 | 谁启动的 | 人话 |
| 批量删除 3 个任务？该操作不可恢复 | 删除这 3 个任务？删除后要重新添加 | 说后果，不说规则 |
| 网络异常，请稍后重试 | 连不上服务，正在自动重试（第 3 次） | 说状态 |
| 操作成功 | 已保存 / 已开始生成 | 说结果 |
| 参数错误 | 并发数要在 1–10 之间 | 说怎么改 |

### 9.3 轮询与离线

- 运行列表 5s（页面可见才轮询）；全局计数 30s；失败退避 5→10→20→30s。
- 轮询 silent，不弹 toast；数据区块标注"更新于 hh:mm:ss"，超过 60s 变琥珀。
- 离线：顶栏胶囊变「离线」+ 页面顶部细横幅（36px，琥珀底），只保留这一个出口。

### 9.4 危险操作

| 级别 | 例子 | 交互 |
|------|------|------|
| L1 | 删除单个任务、移除选中、清空日志视图 | 直接执行 + 5s 撤销 |
| L2 | 取消运行中的执行、删除命名规则 | 确认框（对象 + 后果） |
| L3 | 批量删除、断开 OpenList、清空云盘凭据 | 确认框 + 主按钮危险实心（`#A32C2C`） |

## 11. 落地路线

| 阶段 | 范围 | 验收 | 估算 |
|------|------|------|------|

| 风险 | 对策 |
|------|------|
| 暖紫在长时间监控场景下不如蓝色"冷静" | 状态色仍用绿 / 红 / 琥珀，紫只承担品牌与"进行中"；暗色下紫降到 300 阶 |

| 顶栏吸顶占用 48px，1366×768 下首屏更紧 | 顶栏只放四件轻量元素；按 768 高度校验首屏主行动仍可见 |

## 附录 D：界面元素 → 现有接口 / 字段映射

> 依据 `frontend/src/api/*.ts` 与 `frontend/src/types/*.ts` 实际字段。**结论：所有新元素都能在现有数据上算出来，无需新增接口。**

### D.1「今天」页请求清单（首屏 5 个，均为已有方法）

| # | 调用 | 参数 | 用途 |
|---|------|------|------|
| 1 | `openlistApi.listTasks()` | — | 调度任务数 + 每个任务的 `last_execution` |
| 2 | `openlistApi.listExecutions()` | `page:1, pageSize:20` | 调度最近活动、失败项 |
| 3 | `uploaderApi.listExecutions()` | `page:1, pageSize:20` | 上传最近活动、上传任务状态（按 `task_id` join） |
| 4 | `automationApi.listTasks()` | `page:1, page_size:20` | 待校验数、连续失败数 |
| 5 | `automationRunApi.active()` | — | 运行中阶段、`next_round_at` |

- 不调 `test-connection`（探测服务器会发真实请求，且已有页面负责）；不调 `upload/config`（Token 到期只在「连接与格式」显示）。
- 5 个请求并行、各自 `silent`；任一失败只让对应区块降级，不整页报错。
- 不做额外轮询：运行数量沿用 `stores/running.ts` 的 30s；页面内数据仅在进入与手动刷新时拉取。壳层这 3 个聚合请求属于全局，不计入"页面首屏 ≤5"的预算。

### D.2 元素映射

| UI 元素 | 现有数据来源 | 前端处理 | 缺失时的降级 |
|---------|--------------|----------|--------------|
| 概览句「3 个任务跑完了，1 个需要看一眼」 | 调度 / 上传的 `listExecutions` 中 `status`、`finished_time` | 过滤当天、计数、拼句 | 0 条 → 「今天还没有运行记录」 |
| 流水线卡 · STRM 生成 | `OpenListTask.last_execution`（`status`、`video_success_count/total`、`duration_seconds`） | 运行中优先，否则取最近一条 | `last_execution=null` → 「还没跑过」 |
| 流水线卡 · 云盘上传 | `UploadExecution`（`status`、`file_total/success/failed`、`bytes_uploaded`） | 从执行列表按 `task_id` 取最近一条聚合 | **`UploadTask` 没有 `last_execution` 字段**；无记录即「还没跑过」 |
| 流水线卡 · 自动追更 | `AutomationTask.pending_file_count`、`consecutive_failures`、`is_running`；`AutomationActiveTask.next_round_at` | 状态优先级：运行中 > 待校验 > 连续失败 > 空闲 | 未运行且无 `next_round_at` → 显示 `interval_seconds` 轮询间隔，不编造时间 |
| 需要处理 · 上传失败文件 | `UploadExecution.file_failed`、`error_message` | 取最近 24h、非试运行记录 | 无失败 → 该行不显示 |
| 需要处理 · 待校验文件 | `AutomationTask.pending_file_count` | 汇总 >0 的任务 | 无 → 不显示 |
| 需要处理 · 连续失败 | `AutomationTask.consecutive_failures` | >0 且未运行 | 无 → 不显示 |
| 最近活动（跨模块） | 调度 / 上传的 `listExecutions`（第 1 页）；自动化 `scan_time` + `last_round_no` | 按 `finished_time ?? started_time ?? created_time` 倒序合并取 5；自动化用 `scan_time` 生成"第 N 轮"条目 | 只有 20 条样本，文案写「最近」不写「全部」 |
| 顶栏运行胶囊（数量） | `stores/running.ts` 三个计数（30s） | 直接读 store，零额外请求 | 请求失败 → 「—」，同时连接胶囊变「离线」 |
| 顶栏运行胶囊（百分比） | 同上；`listExecutions` 结果里的 `video_success_count/total`、`file_success+skipped/file_total` | 把 store 的 `pageSize` 由 1 调到 5，按计数加权 | 运行数 >5 → 只显示数量，不显示百分比 |
| 任务卡状态 / 上次耗时 | 调度：`last_execution`；上传：执行列表 join；自动化：`is_running` + `pending_file_count` | `task_id` 关联 | 显示「还没跑过」 |
| 任务卡头像颜色 | 无接口 | 名称哈希取 6 色（第 7.4 节） | — |
| 进度环 | 调度 `video_success_count/total`；上传 `file_success+file_skipped/file_total`；自动化 `checked_file_count/pending_file_count` | 前端算百分比；分母 0 → 不确定态 | 计数缺失 → 不显示环，只留状态胶囊 |
| 「还剩约 N 分钟」 | `started_time` + 当前时间 + 计数 | 线性估算 | 进度 <5% 或 >95% → 不显示 |
| 运行详情 | 现有 WS 帧 + `getExecutionDetail()` / `automationRunApi.getRun()` | 沿用现有连接与回放逻辑 | — |
| 运行记录 | `historySummary()`、`historyByTask()`、`automationRunApi.listRuns()` | 现有分页与筛选 | — |
| 连接与格式 | `getConfig()`、`listServers()`、`testServerConnection()`、`uploaderApi.getConfig()` | 沿用现有 60s 探测节奏 | 探测失败 → 「离线」，不自动重试轰炸 |
| 命名规则 | `listRenameRules()`、`previewRename()` | 现有 | — |
| 搜索 / 命令面板 | `listTasks(keyword)`（三模块均有关键字参数） | 前端过滤 + 路由跳转 | 不做跨模块全文搜索 |
| 批量条 / 卡片表格切换 | 无接口 | 选中集合 + `localStorage` | — |
