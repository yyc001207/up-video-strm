## 0. 摘要：5 个判断，5 个动作

**判断**

1. 产品已经从"一个 STRM 生成器"长成**三条并行流水线**（调度 / 上传 / 自动化），但界面仍是"一个生成器 + 一堆设置页"的组织方式。
2. 这类常驻工具的第一动作通常是"看跑完没有、有没有失败"，而默认页是**全局配置**（`router/index.ts` 中 `/` → `/config`）。
3. 三个模块同构，却各写一遍（执行页 990 / 911 / 1291 行，实时日志 830 / 553 / 587 行），交互只能靠逐页打补丁，历史问题反复出现。
4. 关键状态没有常驻出口：运行数只在导航徽标上，顶栏明确不提供状态入口（见 frontend.md），用户想知道"在跑什么"必须进实时日志页。
5. 视觉体系（品牌色、暗色三层、表格规范）已经达标，缺的是**语义色分层**与**组件契约**——不是换皮能解决的问题。

**动作**

| # | 动作 | 解决什么 |
|---|------|----------|
| A | 新增「总览」为默认首页 | 打开即回答"跑得怎么样、哪里要处理" |
| B | 导航改双层：模块栏 64px + 页面列表 200px | 模块可扩展、切换不丢位置、消除"三个任务配置" |
| C | 全站常驻「状态栏 + 活动中心」 | 运行/失败状态随时可见，日志可就近展开 |
| D | 三个执行页收敛为同一「执行工作台」模板（主从双栏） | 参数区不再被挤到 285px，三套实现变一套 |
| E | 令牌 v2 + 14 个组件契约 | 从"每页自己写一遍"变成"引用同一套" |

## 1. 目标、用户与边界

### 1.1 产品与使用场景

单人自建媒体库用户，在 Windows 上以桌面应用常驻（托盘 + 开机自启），偶发高强度操作。三类真实场景：

| 场景 | 频率 | 时长 | 用户想要的 | 现在要几步 |
|------|------|------|-----------|-----------|
| 看昨晚自动化跑得怎么样、缺哪几集 | 每天 | 10–30 秒 | 一眼看到结果与异常 | 打开落在配置页 → 切模块 → 进历史 → 找记录（4 步） |
| 新下一季，上传 + 生成 STRM | 每周 | 2–5 分钟 | 选任务、设参数、启动、盯着跑完 | 切两个模块，各走一遍执行流程（6+ 步） |

> 频率与时长来自此类单人媒体库工具的常见使用节奏推断；实施前建议用 1–2 次真实使用观察校准，避免按假设排优先级。
| 某任务失败，定位原因并重跑 | 每周 | 1–10 分钟 | 看到错误原文、找到文件、重跑失败项 | 历史 → 详情 → 日志抽屉（3 层） |

### 1.2 用户习惯 → 设计应答

这张表是本方案的设计依据：左边是**可观察的使用习惯**，右边是**具体到组件的应答**，不是抽象口号。

| # | 用户习惯 | 设计应答 |
|---|----------|----------|
| H1 | 后台服务类工具，先看结果再决定动不动手 | 「总览」首屏三段：三条流水线状态 → 需要处理 → 最近活动；状态栏常驻 |
| H2 | 一次处理一批（一季几十个目录），不是一条条来 | 表格批量选择、范围选择（Shift）、跨筛选保留选中、`已选 N / 可选 M` 常显 |
| H3 | 失败时要"那一条"，不要"这一类" | 错误可下钻到文件行；日志支持按 ERROR 过滤、关键字定位、复制原文 |
| H4 | 讨厌被弹窗打断，但怕误删 | 可恢复操作（单条删除）改为 5 秒撤销；不可恢复（清空凭据、批量删除）才用确认框 |
| H5 | 窗口就是工作台，希望"回到刚才那页" | 记住窗口尺寸、侧栏折叠、各模块最后页面、列表筛选与滚动位置 |
| H6 | 路径要能带走（贴到别处、在资源管理器打开） | 所有路径单元带复制按钮；日志目录一键打开（已有能力，入口统一） |
| H7 | 中文小字看不清就放弃 | 正文不小于 13px、元信息不小于 12px、行高 1.5；禁止 11px 正文 |
| H8 | 不信任"看起来在转"的界面，要证据 | 每处异步数据标注"更新于 hh:mm:ss"；重试次数可见；离线只留一个出口 |
| H9 | 桌面用户习惯键盘 | `Ctrl+K` 命令面板、`/` 聚焦搜索、`Esc` 关闭、`Ctrl+Enter` 执行、`Alt+1..4` 切模块 |
| H10 | 夜间使用，深色是默认而非附加 | 深色不是反色：语义色重新取值，日志区、表头、浮层各有层级 |

### 1.3 非目标（本期明确不做）

- 移动端 / 平板适配（窗口最小 1024px，不做手机布局）。
- 多用户、权限、登录（产品定位是无登录本地服务）。
- 报表 / 大屏 / 图表分析（当前数据量不足以支撑，且违背"工具"定位）。
- 更换品牌色与 Logo（`#2b6cf6` 已形成识别，问题不在色相）。
- 国际化（中文单语）。

### 1.4 成功标准（可测，验收时逐条判定）

| # | 标准 | 判定方式 |
|---|------|----------|
| M1 | 打开应用 3 秒内能回答"是否在跑、是否有失败" | 总览首屏含三流水线状态 + 异常清单，无需滚动 |
| M2 | 从任意页面 1 次点击进入运行中任务的日志 | 状态栏 → 活动中心 → 该任务"查看日志" |
| M3 | 1024×680 下主行动始终可见 | 执行按钮固定在面板 footer，面板 sticky |
| M4 | 执行页参数区宽度 ≥ 320px，分段控件不截断 | 1440 与 1280 两档实测 |
| M5 | 12–14px 文字对比度全部 ≥ 4.5:1 | 第 6.3 节表格逐项核验 |
| M6 | 三个执行页共用一套模板、一套样式常量 | 代码评审：无重复布局定义 |

## 2. 现状诊断

### 2.1 结构层

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| S1 | 默认页是配置页 | `router/index.ts`：`/` → `/config`；catch-all 也回 `/config` | 每天第一次打开都落在一次性配置页，用户要再点 2–4 次才能看到运行情况 |
| S2 | 模块列表与页面列表挤在同一列，切换即跳首页 | `App.vue` 220px 内先渲染 4 个模块按钮（36px/项），再渲染当前模块页面；`goModule()` 直接 `push` 该模块第一页 | 模块间来回切换（上传→调度→自动化 是一条真实链路）每次都丢上下文；220px 一列要同时容纳"模块 + 分组 + 页面"三级信息，再加第 5 个模块就必然出现导航滚动 |
| S3 | 同名页面重复三份 | 三个模块各有「任务配置 / 执行管理 / 实时日志 / 任务历史」；执行页 990 / 911 / 1291 行，各自定义三卡比例 | "上传管理与任务调度采用同一套骨架"只能靠人工对齐；1100–1600px 中栏被压到 ≈285px 的历史问题，必须在三个文件里各修一次 |
| S4 | 主行动位置不统一 | 执行按钮在右卡底部、新建在工具栏右侧、保存在抽屉底部 | 用户每换一页都要重新找"下一步在哪"；小屏时主按钮可能落出首屏 |

### 2.2 交互层

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| I1 | 运行状态只有一个出口，且在二级页 | 徽标只挂在「实时日志」导航项；顶栏"不提供运行状态入口"（frontend.md 明示） | 想知道"现在在跑什么"必须先进日志页；状态与操作被绑死 |
| I2 | 日志是"目的地"，不是"伴随视图" | 启动后 `router.push('/xxx/realtime?execs=...')`，离开页面即失去监控 | 用户要么盯着一个页面，要么放弃观察；同时存在三套日志页 |
| I3 | 首访空态断裂 | 任务配置页同时有"默认运行参数"空态与"任务表"空态，两处都有新建入口（ui-review-round2 P1-4 已记录，代码仍为双入口） | 第一次使用不知道该先配参数还是先建任务 |
| I4 | 反馈要么很吵，要么很安静 | 轮询失败曾每 5–10s 弹相同 toast（已修，去重 + 3s）；但"数据多久没更新"没有任何可见证据 | 用户无法区分"真的空闲"与"接口挂了但界面没变" |

### 2.3 视觉层

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| V1 | 语义色只有单一色值，没有"底色 / 描边 / 文字"三件套 | `element-reset.scss` 只定义 `--el-color-success` 等单值 | 状态标签只能靠 12% 透明底凑；`#12b76a` 作文字在白底仅 **2.62:1**，实际不可读 |
| V2 | 导航选中态对比不足 | `App.vue` 选中态 = `color-mix(primary 12%)` 底 + `primary` 文字，实测 **3.90:1**（14px 需 4.5） | 选中项"发灰"，长时间看吃力 |
| V3 | 焦点环不完整 | `global.scss` 只设 `outline-offset: 2px`，未定义 `outline` 颜色与宽度（近期提交移除了默认轮廓） | 实际呈现取决于 UA 默认，深浅主题不一致；键盘用户定位困难 |
| V4 | 字体栈不是为 Windows 写的 | `global.scss` 栈首为 `Helvetica Neue` / `PingFang SC`，Windows 均不存在，中文落微软雅黑、拉丁也落雅黑自带字形 | 小字号拉丁与数字发虚；而雅黑 600 即 Bold，选中态一旦加粗就跳宽（代码注释已记录此坑） |
| V5 | 暗色只有三层，缺"内嵌面板"层 | `dark.scss` 仅 page / card / overlay 三层 | 日志区、参数区、表头与卡片同灰阶，层级靠 1px 边框硬撑 |
| V6 | 徽标语义与对比双错 | 导航徽标 = 琥珀底 + 白字，实测 **2.35:1**；且琥珀在中文界面里首先被读作"警告" | 运行中看起来像"有告警"，且小字看不清 |

### 2.4 结论

现有界面不是"不好看"，而是**用配置页的组织方式承载了流水线工具的使用方式**：入口按"设置项"分级，状态按"页面"存放，操作按"页面作者"各写一套。因此本方案不动品牌、不动技术底座，只重排三件事：**入口顺序、状态出口、组件契约**。

## 3. 设计原则

| # | 原则 | 做法 | 反例（当前存在） |
|---|------|------|------------------|
| P1 | **状态先行** | 任何页面都能在 1 屏内知道"在跑什么、跑到哪、有没有失败"；状态用词、颜色、形状全站唯一 | 运行数藏在导航徽标里 |
| P2 | **一条流水线，一套模式** | 三个模块共享「配置 → 执行 → 监控 → 复盘」同一骨架、同一组件、同一文案结构 | 三套执行页各自实现 |
| P3 | **就地反馈** | 能用行内提示就不用 toast，能用 toast 就不用弹窗；状态变化发生在原地，不跳页 | 启动后强制跳转日志页 |
| P4 | **渐进披露** | 首屏只放决策必需项；低频参数进"高级"折叠或抽屉 | 默认运行参数大卡占据任务页首屏 |
| P5 | **桌面原生** | 按 Windows 的字体、DPI、窗口、键盘、文件习惯设计，不照搬 Web 后台模板 | 字体栈以 macOS 字体开头 |

> 示意图说明：左侧模块栏实际宽 64px、**只显示图标**（悬停出全称），图中文字标注仅为示意；第二列才是 200px 的页面列表。

**为什么是双层，而不是手风琴**

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 现状（模块按钮 + 当前模块页面） | 实现最简单 | 切换即跳首页、丢失上下文；模块名与页面名重复 | 淘汰 |
| 单列手风琴（全部模块展开） | 单列、结构直观 | 16 个页面全展开约 800px，1366×768 下必须滚动；三个"任务配置"同时可见，反而更乱 | 备选（宽度 < 1100 时退化为该形态） |
| **模块栏 + 页面列表（推荐）** | 模块位置恒定、只显示当前模块页面、可记忆每模块最后页面 | 多占 44px 横向空间 | **采用** |

**规格**

| 元素 | 规格 |
|------|------|
| 模块栏 | 宽 64px；项 44×44，图标 20px；选中态 = 12% 主色底 + 左侧 3px 主色条；`title` + `aria-label` 全称 |
| 页面列表 | 宽 200px；项高 36px，图标 16px；分组标题 11px/500/次要色（仅拉丁字母加 0.02em 字距，中文 0） |
| 折叠 | 可整体折叠为 64px（只留模块栏），状态存 `localStorage`；≥1280 默认展开 |
| 徽标 | **只表达"运行中"**，用主色底 + 白字（≥18px 高）；不再用琥珀 |
| 记忆 | 每模块记住最后访问页面（`up-video-strm:last-route:{module}`），点模块图标回到该页 |

### 4.3 导航分层调整：全局配置下沉

- 全局配置是**一次性动作**（服务器、格式、云盘凭据），不是工作流的一环。它现在占着一级入口的位置，与"任务调度/上传管理/自动化"并列，会让用户误以为"配置也是一条流水线"。
- 调整：从模块栏移到页面列表底部的「配置」分组，与「设置」相邻；**路由 `/config` 不变、页面内容不变**，仅换层级与图标位置。
- 风险与对策：老用户会找不到——在版本更新说明中写明；首版保留 `/config` 直达；不改变托盘"设置…"跳转（仍是 `/settings`）。

### 4.4 路由迁移（只增不改）

| 变更 | 说明 |
|------|------|
| `/` | 由"重定向 `/config`"改为渲染**总览** |
| catch-all | 由"重定向 `/config`"改为重定向 `/` |
| `/schedule/config` | 保持重定向 `/config`（旧链接兼容） |
| `/settings` | **必须保持不变**：桌面托盘经 `window.__upVideoStrmNavigate('/settings')` 跳转（见 `main.ts` / `desktop.py`） |
| 其余 13 条业务路由 | 路径全部不变，仅页面实现替换；`?execs=` 传参保留，作为"接力上下文"而非唯一入口 |

### 4.5 全局入口

### 5.3 四类页面骨架

所有页面只允许属于以下四类之一，**不允许第五种骨架**。

**① 列表页**（任务配置、重命名规则、任务历史）

```
[工具栏 32]  左：搜索/筛选   右：刷新 + 次级操作 + 主操作
[表格卡 flex]  表头 40 固定 / 行 40 / 内部滚动 / 分页 44 在卡片底部
```

**② 工作台**（三个执行管理）

```
[主区 flex, min 480]                    [侧栏 340, sticky, 独立滚动]
  筛选行                                 参数分组（可折叠）
  任务表（内部滚动）                     已选摘要
  正在执行（可折叠，内部滚动）           footer：[清空] [执行任务] 常驻
```

**③ 监控页**（三个实时日志）

```
[任务条 40]  执行选择 / 状态 / 用时 / 操作
[进度带 72]  计数 + 阶段 + 进度 + 当前文件
[过滤条 36]  级别 / 关键字 / 跟随 / 行号
[日志区 flex, min 320]  终端
```

**④ 设置页**（全局配置、设置）

```
[内容最大 960 居中]  分区标题 + 说明 + 卡片，单列纵向
                    ≥1440 时允许 2 列等宽卡片（仅格式与云盘）
```

### 5.4 滚动与固定

- **一个视口只允许一个纵向滚动容器**：列表页滚动在表格卡内，工作台滚动在主区与侧栏各自内部，监控页滚动在日志区内。页面本身不出现整页滚动条（沿用现有约定）。
- 固定元素只有四个：顶栏、状态栏、工作台侧栏、抽屉 footer。表头在卡片内 `sticky`。
- 侧栏与主区滚动互不影响：参数区变长不应把任务列表顶走。
- 抽屉打开时锁定背景滚动，关闭后焦点回到触发元素。

### 5.5 栅格与密度

- 12 列栅格，槽宽 16px（< 1280 时 12px），卡片间距 16，区块间距 24。
- 表格行高默认 40px；提供"紧凑"（32px）作为 P2 可选，仅影响表格，不影响表单与按钮。
- 控件高度：默认 32px，小号 28px，大号 36px；同一行内不得混用三种高度。

### 6.4 字体

**字体栈（Windows 优先，macOS 兜底）**

```
UI:   "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI",
      "Microsoft YaHei", "PingFang SC", system-ui, sans-serif
MONO: "Cascadia Mono", "Cascadia Code", Consolas,
      "Microsoft YaHei UI", "PingFang SC", monospace
```

**字重规则（必须遵守，否则中文会跳宽）**

| 场景 | 字重 | 原因 |
|------|------|------|
| 正文、表格、按钮、导航 | 400 | 微软雅黑无 500，500 会回退 Regular，等于没生效 |
| 页面标题、卡片标题 | 600 | 雅黑 600 映射 Bold，仅用于大字号，不用于 12–14px 行内 |
| 选中态 / 强调 | **禁止改字重**，用底色 + 指示条 + 颜色 | 600 会让导航文字变宽 1–2px，产生"跳位" |

**字号阶**

| 令牌 | 值 | 行高 | 用途 |
|------|----|------|------|
| `--fs-11` | 11px | 16 | 仅分组标签、极短元信息（不用于句子） |
| `--fs-12` | 12px | 18 | 表头、时间戳、辅助说明 |
| `--fs-13` | 13px | 20 | 表单帮助、页面说明、日志 |
| `--fs-14` | 14px | 21 | 正文、表格、按钮、导航 |
| `--fs-16` | 16px | 24 | 卡片标题 |
| `--fs-20` | 20px | 28 | 页面标题 |
| `--fs-24` | 24px | 30 | 总览大数字 |
| `--fs-28` | 28px | 34 | 总览 hero 数字（仅一处） |

**排版细节**

- 中文一律 `letter-spacing: 0`；只有全大写拉丁标签可用 `0.02em`。
- 所有数字（计数、耗时、百分比、版本号）加 `font-variant-numeric: tabular-nums`。
- 日志用 MONO，12.5px / 20px 行高；默认不换行，横向滚动，避免长路径把行高撑乱。
- 不用 `text-align: justify`；中英混排不在标点两侧加空格（由字体自然处理）。

| 搜索 | 关键字高亮（警告底），匹配计数 `3/17`，↑↓ 跳转，当前项加描边 |
| 复制 | 右键菜单：复制此行 / 复制全部 / 复制路径（自动识别路径片段） |

| 项 | 规格 |
|----|------|

### 7.8 反馈

| 类型 | 使用场景 | 规格 |
|------|----------|------|
| 行内提示 | 字段级校验、目录不可用、参数冲突 | 控件下方，13px，不打断 |
| Toast | 操作结果（保存成功、复制成功、启动失败） | 3s，按 key 去重，最多同时 3 条，右下角，可手动关闭 |
| 常驻通知 | 需要用户注意但不阻断（日志中的 alert 帧） | 页面顶部 inline alert，可关闭，不自动消失 |
| 确认框 | 不可恢复 / 影响多个对象 | 标题写对象与数量，正文写后果，主按钮用动作动词（"删除 3 个任务"），不用"确定" |
| 撤销 | 单条删除、批量移除选中 | 5s 内可撤销，toast 内带"撤销"按钮 |
| 离线横幅 | 后端不可达 | 顶栏下方唯一出口，文案含"正在自动重试"，恢复后自动消失并 toast 一次"已恢复连接" |

**反馈分级规则**：可恢复 → 撤销；影响单一对象且可重建 → 行内提示；影响多个对象或不可恢复 → 确认框。**任何操作不允许同时出现 toast + 弹窗。**

### 7.9 空态、加载、错误

| 类型 | 图标 | 标题 | 说明 | 主行动 |
|------|------|------|------|--------|
| 首次空态 | 40px 线性图标 | 还没有任务 | 一句话说明这个模块能做什么 | 「新建任务」+ 次要「查看快速添加」 |
| 无结果 | 32px 搜索图标 | 没有匹配的任务 | 显示当前筛选条件 | 「清除筛选」 |
| 未配置 | 32px 警示图标 | 先完成服务器配置 | 说明缺哪一项、影响什么 | 「去配置」（深链到 `/config`） |
| 加载失败 | 32px 断线图标 | 数据加载失败 | 显示错误摘要 + 时间 | 「重试」 |

**规则**：一个页面同一时刻只允许出现**一个**空态；页面上方的参数卡不得单独拥有空态（改为摘要条 + 「未设置」标签）。

### 7.10 活动中心与命令面板

**状态栏**：`● 运行中 2 · 1 项待处理 · 更新于 12:31:08` + 右侧「活动中心」。离线时整条变警告底并显示「后端未连接」。

│ 4/12 文件 · 当前 xxx.mkv

| 任务（未执行过） | idle | 未执行 | 中性空心点 |
| 文件（上传） | pending / uploading / uploaded / skipped / failed | 待上传 / 上传中 / 已上传 / 已跳过 / 失败 | 中性 / 主色 / 成功 / 中性 / 失败 |
| 自动化轮次 | waiting / checking / done / failed | 等待中 / 校验中 / 已完成 / 失败 | 中性 / 主色 / 成功 / 失败 |
| 连接 | online / offline / unconfigured / checking | 在线 / 离线 / 未配置 / 检测中 | 成功 / 失败 / 中性 / 中性+呼吸 |
| 待办 | pending-review | 待处理 N | 警告 |

规则：**同一个词只有一个含义**。"完成"不再既指"执行结束"又指"成功"；"异常"不再既指网络错误又指文件失败。

### 9.2 轮询、离线与重试

| 项 | 规则 |
|----|------|
| 运行中列表 | 5s，页面可见时才轮询（沿用现有实现） |
| 全局计数 | 30s，`document.hidden` 时跳过 |
| 退避 | 连续失败：5 → 10 → 20 → 30s 封顶；恢复后重置 |
| 静默 | 轮询请求一律 silent，不弹 toast；失败只更新状态栏与"更新于" |
| 证据 | 所有异步区块显示"更新于 hh:mm:ss"（>60s 未更新时变警告色） |
| 离线 | 全站唯一横幅（顶栏下），文案"无法连接后端服务，正在自动重试（第 N 次）"；恢复后消失并 toast 一次 |
| 手动刷新 | 每个列表页工具栏最右保留刷新按钮，点击后按钮转 600ms 再复原 |

### 9.3 危险操作分级

| 级别 | 例子 | 交互 |
|------|------|------|
| L1 可恢复 | 删除单条任务、移除已选项、清空日志视图 | 直接执行 + 5s 撤销 toast |
| L2 影响明确 | 删除重命名规则（被引用时禁止）、取消运行中执行 | 确认框：对象 + 数量 + 后果 |
| L3 不可恢复/影响面大 | 批量删除、删除服务器、清空云盘凭据、重跑全部失败项 | 确认框 + 需输入对象数量或名称确认；主按钮为失败色实心 |

### 9.4 文案与格式

- 按钮用动词 + 对象：`新建任务` / `执行任务` / `重跑失败项`；禁止 `确定` / `提交` / `是`。
- 错误三段式：**发生了什么 + 为什么 + 怎么办**。例："写入失败：目标目录无写权限。请检查 OpenList 父级目录权限，或在任务配置中更换输出目录。"
- 时间：默认 `YYYY-MM-DD HH:mm:ss`（北京时间）；24 小时内可显示"3 小时前"，`title` 给绝对时间。
- 耗时：`4m12s`；超过 1 小时 `1h04m`；小于 1 秒 `<1s`。
- 数量：千分位；计数列 0 显示 `—`；"共 128 个文件" 不在数字与单位间加空格。

## 10. 无障碍与平台适配

### 10.1 WCAG AA 清单

- [ ] 12–14px 文字对比度 ≥ 4.5:1（第 6.3 节全部通过）。
- [ ] 图形/边框对比度 ≥ 3:1（复选框、进度条、输入框描边）。
- [ ] 焦点可见：2px 主色环 + 2px offset，深浅主题各自可辨。
- [ ] 键盘可达：所有操作可用键盘完成；抽屉/弹窗焦点陷阱；关闭后焦点归还。
- [ ] 触控/点击目标 ≥ 32×32（图标按钮 32，行内小按钮 28 但加 4px 透明外扩）。
- [ ] 状态不只靠颜色：状态点 + 文字；失败行额外有图标与文案。
- [ ] `prefers-reduced-motion` 生效；日志与进度不做动画。
- [ ] 文本放大 200% 不截断关键操作（顶栏标题可省略，主按钮不换行）。

### 10.2 键盘映射

| 键 | 行为 | 范围 |
|----|------|------|
| `Ctrl+K` | 命令面板 | 全局 |
| `Alt+1..4` | 总览 / 任务调度 / 上传管理 / 自动化任务 | 全局 |
| `/` | 聚焦当前页搜索框 | 列表页 |
| `Esc` | 关闭最上层浮层 | 全局 |
| `Ctrl+Enter` | 执行已选任务 | 工作台 |
| `Space` | 勾选当前行 | 表格 |
| `Shift+Click` | 范围选择 | 表格 |
| `F5` | 刷新当前页数据（桌面端拦截默认刷新） | 全局 |

### 10.3 Windows 适配

- DPI 100%–200%：全部使用 px + 系统缩放；边框不小于 1px；图标提供 16/20 两档，不用位图缩放。
- 字体：优先 `Segoe UI Variable`（Win11）/ `Segoe UI`（Win10）；中文回落 `Microsoft YaHei UI`。
- 窗口：最小 1024×680；记住上次尺寸/位置/最大化状态（由桌面外壳负责，前端只响应）。
- 托盘：菜单"打开主界面 / 设置… / 退出"；"设置…"仍跳 `/settings`。
- 滚动条：WebView2 默认细滚动条，样式沿用现有 8px 方案；日志区横向滚动条常驻可见。
- 快捷键不注册系统级热键（避免与其他软件冲突），只在窗口内生效。

### 10.4 主题

- 三态：浅色 / 深色 / 跟随系统；切换无闪烁（沿用首屏预加载）。
- 深色不是反色：主色提亮到 400 阶；语义色改用暗色组；表面分四层（page / card / panel / overlay）。
- 日志区在两套主题都使用"内嵌面板"层，保持与卡片可区分。
- 切换主题时不做过渡动画（避免大面积闪动）。

## 11. 落地路线与验收

### 11.1 五阶段

> 工时为粗略估算，用于排期参考，不是承诺；每阶段独立提交、独立验收、可单独回滚。

| 阶段 | 范围 | 产出 | 验收 | 估算 |
|------|------|------|------|------|
| **P0 基线与令牌** | 截图基线（16 路由 × 明暗）、令牌 v2、字体栈、焦点环、语义色四件套 | 样式层改造；无结构变化 | 全站视觉无回归；对比度表逐项通过；三套主题截图对比 | 2–3 天 |
| **P1 壳层与导航** | 模块栏 + 页面列表、顶栏操作区、状态栏、默认页改总览、快捷键 | `AppShell`、`ActivityCenter`、总览页 | 16 路由全部可达；`/settings` 托盘跳转正常；1024 下不溢出；`/` 落在总览 | 4–5 天 |
| **P2 工作台收敛** | `WorkbenchLayout` + `DataTable` + `StatusPill` + `EmptyState`；三个执行页迁移；历史页改造 | 一套模板替换三套实现 | 三模块功能逐项对齐（对照现有功能清单）；参数区 ≥320；无重复布局样式 | 5–7 天 |
| **P3 监控与反馈** | `LogTerminal` 升级、三套实时日志迁移、活动中心日志预览、撤销/确认分级 | 统一监控台 | 启动后可在任意页面看到进度；日志过滤/搜索/跟随可用；结束态正确 | 3–4 天 |
| **P4 打磨** | 命令面板、空态文案、错误态、文档与截图、手册更新 | 命令面板、`manual/images` 重拍 | 首访引导可走通；16 张截图更新；文档与实现一致 | 2–3 天 |

**迁移策略**：新组件与旧页面并存，按模块逐个切换（先自动化 → 上传 → 调度，从页面最大、问题最多的开始验证模板），每切换一个模块删除对应旧样式，禁止"新旧两套同时长期存在"。

**风险**

| 风险 | 影响 | 对策 |
|------|------|------|
| 导航改造让老用户找不到入口 | 中 | 保留全部路由；更新说明中给出对照表；首版不删除任何页面 |
| 三模块"看起来一样"后，模块差异被抹平 | 中 | 模板只统一**布局与状态**，模块特有参数分组与阶段步骤保留差异 |

| 组件抽取引发样式回归 | 中 | P0 先建截图基线；每阶段做像素对比；样式改动集中在令牌层 |
