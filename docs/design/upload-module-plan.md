# 上传管理模块 · 设计计划

> 状态：计划评审中（未实施）
> 模块定位：自动上传本地视频到 123 云盘（开放平台 API）
> 页面结构参考：任务调度模块（`frontend/src/views/schedule/`、`backend/app/business/openlist/`）

## 1. 需求概述

自动完成「扫描本地文件 → 过滤视频 → 重命名 → 上传 123 云盘」的完整流水线，并提供任务配置、重命名规则管理、执行控制、实时日志与任务历史。

原始需求中的重复校验策略：

- 在重命名阶段，与 123 云盘文件列表对比，文件名相同即视为冲突；
- 冲突时按执行参数决定：**覆盖**（删除云盘旧文件后上传新文件）或**不覆盖**（跳过不上传）。

本文档为该需求的优化版计划，变更点均有标注。

## 2. 页面结构

对齐任务调度模块，新建 `frontend/src/views/upload/`。原计划 5 个子模块中「任务配置」不单开页面：

| 页面 | 对应调度模块 | 说明 |
|------|--------------|------|
| `UploadManage.vue` | `TaskManage.vue` | 承载重命名规则列表与扫描参数 |
| `Execution.vue` | `Execution.vue` | 执行参数 + 任务配置卡片 + 启停控制 |
| `RealtimeLog.vue` | `RealtimeLog.vue` | websocket 实时日志 |
| `TaskHistory.vue` | `TaskHistory.vue` | 文件粒度历史记录 |
| `components/` | `schedule/components/` | 目录树等复用组件（参考 `DirTreePanel` 模式） |

**任务配置**：作为「执行管理」页顶部的独立卡片（或折叠面板），与执行参数同屏。配置项：123 云盘开放平台 **clientID + clientSecret**（开放平台凭据是两个值，非单一 key；加密存储、回显脱敏）、目标目录（目录树选择器）、连接测试按钮。

## 3. 上传流程（优化后）

```
扫描本地目录 → 过滤视频文件 → 应用重命名规则 → 生成「预上传清单」
→ 重复校验（对比 123 云盘目标目录）→ 按冲突策略逐文件执行 → 逐条记录状态
```

### 优化点 1：校验从「重命名阶段」拆为「清单 + 校验」两步

- 重命名阶段只产出待传清单：`原路径 / 新文件名 / 大小 / 扩展名`；
- 任务启动时分页拉取 123 云盘**目标目录**的文件列表并缓存，校验在本地清单与缓存列表间进行，不逐文件调 API；
- 收益：节省限流额度；清单可支撑「执行前预览/确认」（dry-run）；失败重跑时只需处理差异部分。

### 优化点 2：覆盖策略禁止「先删后传」

先删后传存在中间态风险：删除成功但上传失败 → 云盘文件永久丢失。调整为：

1. 先上传新文件（视 API 能力决定直传或临时名后改名）；
2. 上传成功后，再删除旧文件，并在历史记录中留存被删文件的 fileID + 文件名（123 云盘删除进回收站，可人工找回）；
3. 上传失败则保留旧文件，该条目标记失败、可重跑。

### 优化点 3：冲突策略由两档扩为三档

| 策略 | 行为 |
|------|------|
| 覆盖 | 上传新文件 → 成功后删旧文件（见优化点 2） |
| 跳过 | 不上传，记录「已存在，跳过」 |
| 追加后缀 | 新文件名追加序号（如 `name (1).mp4`）后上传，适合新旧都保留的场景 |

策略归属「执行管理」页的执行参数（与原设计一致）。

## 4. 子模块设计

### 4.1 任务配置（并入执行管理页）

- clientID / clientSecret：加密存储，回显脱敏；
- **access_token 自动获取与刷新**：开放平台 token 有效期短，由 service 层自动续期，用户不手填 token；
- 目标目录：目录树选择器；
- 「测试连接」按钮：验证凭据有效性。

### 4.2 重命名规则（UploadManage 页）

- 规则列表按顺序应用，支持模板变量：
  - 原文件名、去扩展名原名、扩展名；
  - 自定义前缀 / 后缀；
  - 日期时间（可配置格式）；
  - 序号（可配置起始值与补零位数）；
  - 剧集/季数正则提取（可后置到二期）；
- **非法字符清洗**：Windows 保留字符 `\ / : * ? " < > |` 及云盘限制字符统一替换，文件名长度截断，避免上传报错；
- **重命名预览（dry-run）**：展示「原文件 → 新文件名」对照表，确认后才进入上传流程；
- 扫描参数：扫描目录、是否递归、排除目录、视频格式（**建议复用全局配置的 `video_formats`**，与 openlist 模块一致，避免两套格式配置漂移）。

### 4.3 执行管理（Execution）

- 执行参数：冲突策略（三档）、并发数（123 云盘有 **QPS 限流**，service 层内置限流器，默认并发 1–2）、分片大小、失败重试次数；
- 大文件分片上传 + **断点续传**（开放平台 v2 上传为分片模式，天然支持）；
- 任务控制：启动 / 暂停 / 恢复 / 取消；
- 定时执行：一期不做，后续评估复用现有调度引擎。

### 4.4 实时日志 / 任务历史

- 复用 `execution_logger.py` / `task_status_manager.py` / websocket 推送模式，日志级别与 openlist 模块一致；
- 任务历史按**文件粒度**记录：`成功 / 跳过(已存在) / 覆盖(含旧文件 fileID) / 失败(原因+所处阶段)`；
- 支持「仅重跑失败项」；
- 覆盖条目留存被删文件 fileID + 文件名，作为回收站找回依据。

## 5. 后端结构（对齐 openlist 模块）

```
backend/app/business/uploader/
├── schema.py            # Pydantic 模型：配置 / 规则 / 任务 / 历史
├── pan123_api.py        # 123 云盘开放平台封装：token 刷新、限流、列目录、分片上传、删除
├── rename_engine.py     # 重命名规则引擎 + 非法字符清洗
├── execution_engine.py  # 流水线：扫描→过滤→重命名→校验→上传
├── execution_logger.py  # 参考 openlist 同名模块
└── task_status_manager.py

backend/app/api/uploader.py   # API 路由
```

前端配套：`frontend/src/api/uploader.ts`、`frontend/src/types/uploader.ts`、`frontend/src/views/upload/`。

## 7. 实施阶段划分（待决策点确认后细化）

1. **阶段一**：123 云盘 API 封装（token 刷新、限流、列目录、上传、删除）+ 任务配置；
2. **阶段二**：扫描 / 过滤 / 重命名引擎 + 预览；
3. **阶段三**：冲突校验 + 执行引擎 + 执行管理页；
4. **阶段四**：实时日志 + 任务历史 + 失败重跑。
